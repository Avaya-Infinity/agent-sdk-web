    Class Interaction

    A contact center interaction between an agent and a customer.

    Lifecycle

    1. Interaction arrives - currentStatus is PENDING.
    2. Agent calls accept (or reject to decline).
    3. Status transitions to CONNECTED; agent can perform actions on it like mute, hold, transfer, or start a conference.
    4. Agent wraps-up the interaction
    5. Interaction status moves to WRAP_UP; agent records notes and classification codes.
    6. Agent calls close or complete to finalize; status becomes COMPLETED.

    Example

    // 1. Subscribe to incoming interactions on the user object
    user.subscribe(UserEventType.INTERACTION_RECEIVED, async ({ payload }) => {
        const interaction = payload.interaction;

        // 2. Accept the call
        await interaction.accept();
        console.log("Accepted interaction:", interaction.interactionId);

        // 3. React to call events
        interaction.subscribe(InteractionEventType.INTERACTION_CALL_DISCONNECTED, () => {
            console.log("Call ended - entering wrap-up");
        });

        interaction.subscribe(InteractionEventType.INTERACTION_WRAP_UP, async () => {
            // 4. Record notes during wrap-up
            await interaction.setNotes("Customer requested a follow-up call next Tuesday");

            // 5. Close as resolved
            await interaction.close(ResolutionStatus.RESOLVED);
        });
    });

    Reactivity

    The SDK maintains a single Interaction instance per interaction and mutates its fields in place as state changes — the object reference is stable across updates. Framework consumers (React, Vue, etc.) that rely on reference equality for change detection must therefore trigger their own re-render on each subscribed event — for example by bumping a version counter, re-emitting the enclosing array, or lifting the data into a store that produces a fresh snapshot per event.
