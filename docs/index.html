    Agent SDK

    Overview

    The Avaya Infinity Agent SDK provides functionality for contact center agents to authenticate, manage their status, handle queues, and process customer interactions on the Avaya Infinity™ platform.

    Installation

    Note: This package is not yet published to npm. For local development, use the monorepo workspace setup described in the root README.

    To install the Agent SDK (once published), run the following command:

    npm install --save @avaya/infinity-agent-sdk

    The SDK exports a set of types and classes. The class AvayaInfinityAgentSdk is the entry point for SDK initialization. It can be imported as follows:

    import { AvayaInfinityAgentSdk } from "@avaya/infinity-agent-sdk";

    Usage

    Initialization

    Before any operation can be performed, the SDK must be initialized. The initialization process handles OAuth authentication, establishes WebSocket connections, and returns a User object representing the authenticated agent.

    The SDK supports two OAuth authentication modes via the oAuthMode parameter:

    Mode Description init() calls Best for
    redirect (default) Navigates the page to the IdP login page Two (before and after redirect) Standalone SPAs
    popup Opens the IdP login in a popup window One Iframe-embedded apps (e.g., Salesforce)

    Redirect mode (default)

    In redirect mode, calling init() navigates the browser to the IdP login page. After the user authenticates, the IdP redirects back to oAuthRedirectUri with an authorization code. The application must call init() again on the redirect landing page to complete the flow.

    import { AvayaInfinityAgentSdk } from "@avaya/infinity-agent-sdk";

    const user = await AvayaInfinityAgentSdk.init({
      avayaInfinityHost: "api.avayacloud.com",
      clientId: "your-client-id",
      oAuthRedirectUri: window.location.origin,
    });

    Note: In redirect mode, the first init() call triggers a page redirect and returns a never-resolving promise. Ensure your application calls init() on every page load so it can complete the flow after the IdP redirects back.

    Popup mode

    In popup mode, init() opens the IdP login page in a popup window. The current page is never navigated away, and the returned promise resolves with the User once authentication completes in the popup. This mode requires a callback page (see OAuth Callback Page) hosted at the oAuthRedirectUri.

    import { AvayaInfinityAgentSdk } from "@avaya/infinity-agent-sdk";

    // Must be called inside a user click handler to avoid browser popup blockers
    const user = await AvayaInfinityAgentSdk.init({
      avayaInfinityHost: "api.avayacloud.com",
      clientId: "your-client-id",
      oAuthRedirectUri: "https://your-app.com/callback.html",
      oAuthMode: "popup",
    });

    Important: Browsers block popups that are not opened from a direct user gesture (e.g., a button click). Ensure init() is called synchronously within a click event handler.

    OAuth Callback Page

    When using popup mode, the IdP redirects the popup window to the oAuthRedirectUri after authentication. A callback page must be hosted at that URI to send the authorization code back to the SDK.

    Using the SDK-provided callback page

    The SDK ships a callback.html file that you can copy and host at your redirect URI. It handles extracting the authorization code from the URL and posting it back to the opener window automatically.

    Using a custom callback page

    If you need a custom callback page, the SDK exports a handleOAuthCallback() helper function:

    // In your custom callback page (e.g., my-callback.ts)
    import { handleOAuthCallback } from "@avaya/infinity-agent-sdk";

    handleOAuthCallback();

    This function extracts the code and error query parameters from the URL, sends them to the opener window via postMessage, and closes the popup.

    Managing Agent Status

    Agents can change their availability status using reason codes:

    // Get available reason codes
    const reasons = await user.getAssignableReasonCodes();

    // Change status to a specific reason
    await user.changeStatus(reasons[0]);

    // Get current status
    const currentStatus = await user.refreshStatus();

    Working with Queues

    Agents can login/logout from queues to receive interactions:

    // Get assigned queues
    const queues = user.getAssignedQueues();

    // Login to a queue
    await queues[0].login();

    // Logout from a queue with a reason
    const reasons = await user.getAssignableReasonCodes();
    await queues[0].logout(reasons[0]);

    Handling Interactions

    Subscribe to receive new interactions and manage their lifecycle:

    // Subscribe to new interactions
    user.subscribe("interactionReceived", (event) => {
      const interaction = event.payload.interaction;
      console.log("New interaction from:", interaction.customer.name);
    });

    // Accept an incoming interaction
    await interaction.accept();

    // Set notes during the interaction
    await interaction.setNotes("Customer inquiry about account");

    // Disconnect the call (for voice interactions)
    await interaction.disconnectCall();

    // Close the interaction with resolution status
    await interaction.close(ResolutionStatus.RESOLVED);

    // Complete the interaction
    await interaction.complete();

    Events

    The SDK provides events for monitoring state changes:

    User Events

    Event Description
    userStatusChanged Fired when the agent's status changes
    queueStatusChanged Fired when queue login status changes
    interactionReceived Fired when a new interaction is received 
    user.subscribe("userStatusChanged", (event) => {
      console.log("Status changed to:", event.payload.status);
    });

    Interaction Events

    Event Description
    interactionAccepted Fired when an interaction is accepted
    interactionRejected Fired when an interaction is rejected
    interactionCallDisconnected Fired when the call is disconnected
    interactionWrapUp Fired when entering wrap-up phase
    interactionCompleted Fired when the interaction is completed
    interactionNotesUpdated Fired when notes are updated 
    interaction.subscribe("interactionWrapUp", (event) => {
      console.log("Interaction entered wrap-up phase");
    });

    Shutting Down

    To properly clean up and logout:

    await AvayaInfinityAgentSdk.destroy();

    Test Harness

    The SDK includes a standalone test harness — a zero-build-step HTML page for testing the SDK in isolation, without the demo-app. Use it to quickly reproduce customer issues and determine whether a bug is in the SDK or the demo-app.

    # Build the SDK first
    pnpm -F ./sdk build

    # Launch the harness (opens browser automatically)
    pnpm -F ./sdk run-harness

    The harness provides:

    • Config panel for connection settings (persisted to localStorage)
    • Buttons for all agent operations (status, queues, interactions, transfers, conferences)
    • Live event log with timestamps, filtering, and JSON export
    • Console globals (window.SDK, window.user, window.intr, window.interactions) for debugging
    • Multiple simultaneous interaction support

    To verify the harness covers all public API methods and events:

    pnpm -F ./sdk check-harness

    See test-harness/README.md for full documentation.

    Logging

    The SDK supports configurable log levels. Pass the logLevel parameter during initialization:

    import { AvayaInfinityAgentSdk, LogLevel } from "@avaya/infinity-agent-sdk";

    const user = await AvayaInfinityAgentSdk.init({
      avayaInfinityHost: "api.avayacloud.com",
      clientId: "your-client-id",
      oAuthRedirectUri: window.location.origin,
      logLevel: LogLevel.DEBUG,
    });

    Available log levels: ERROR, WARN, INFO, DEBUG, OFF
